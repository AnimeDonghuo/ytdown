# YouTube and Terabox downloader Telegram bot

The bot defaults to **YouTube mode**. Use `/change` to select YouTube-only or Terabox-only links; mode settings are per user and reset on restart. Send a YouTube video or public playlist URL in YouTube mode. For a video, it asks the [Samra YouTube API](https://samra-youtube-api.antideploy.com/) for **actually downloadable** MP4 qualities and MP3 audio, then displays toggle buttons. Select as many as you like and tap **Done**. The provider can take 1–2 minutes (the bot waits up to 4 minutes per lookup). For a playlist, the bot first reports the video count (up to 5,000 public entries). Reply with an **inclusive range** such as `1-29` or `200-300` (at most 150 entries per job), then select 360p, 480p, 720p, 1080p, 1440p (2K), and/or 2160p (4K). After Done it discovers only that range of public video IDs with `yt-dlp` and queries the API per video. Qualities absent from an individual API response are skipped, **not replaced with another quality**. Files are transferred and sent one at a time.

Titles come from YouTube first (oEmbed with a `yt-dlp` backup for single videos, and YouTube's playlist entries for playlists). If neither YouTube method returns a title, the bot uses **that video's API title**; only if that is missing does it use the video ID. The filename and Telegram caption end with the chosen quality, for example `Actual Video Title [480p].mp4` and `Actual Video Title [480p]`; audio is labeled `[MP3]`. A subtitle marker such as `[EngSub]` or `[MultiSub]` (also accepted in parentheses, any case) is removed from the title and placed **after** the quality, for example `Episode 15 [360p] [MultiSub]`. For playlist items (and multi-item Terabox folder ranges), the caption and live-status title start with the position, for example `2/39 · One Way or Another Episode 15 [360p] [MultiSub]`, and the filename starts with a zero-padded index, for example `02-39 One Way or Another Episode 15 [360p] [MultiSub].mp4` (`002-150` when the total is 150). Single videos have no position prefix. Videos prefer the **API-provided thumbnail URL**; if it returns a mostly white placeholder or fails, the bot tries YouTube's reliable HQ image before max-resolution. Thumbnails are resized/compressed under 18 KiB (Telegram may silently ignore larger images) and uploaded as a `.jpg` with video dimensions. Videos are sent as streamable MP4 so they **stay playable inline**; a document is only used as a last resort if Telegram refuses the file as video. After a video is delivered, the bot makes one bounded check of the still-image thumbnail Telegram returned (read in 64 KiB requests and capped at 256 KiB, then decoded locally). If that still is missing, unreadable, or white, the bot **replies to the video** with the prepared JPEG as a separate cover photo. A cover problem never causes the video to be uploaded again; it is only logged. If Telegram rejects the prepared thumbnail on the send itself, the already-uploaded file is re-sent once without it, because that send did not succeed. Container logs record whether a usable thumbnail was prepared and whether a cover photo was sent. `ffprobe` reads the bounded beginning/end of the actual MP4 to supply Telegram its **duration and real frame dimensions**, without downloading a second full copy; the API duration (including `HH:MM:SS` strings) and thumbnail shape are fallbacks when the stream cannot be probed. Rotated videos have their display dimensions swapped when ffprobe reports a rotation. Ratios cannot be corrected if black/white borders are actually encoded into the source frames. The `ffmpeg`/`ffprobe` package makes the Docker image larger, so a cold Koyeb image download may take longer.

### Terabox mode

Switch with `/change` → **Terabox**, then send an HTTPS Terabox share URL (including `terasharefile.com/s/...`). The bot calls the [Samrat Terabox API](https://samratbdownload.krishnalucky193.workers.dev/?url=) and shows the formats/qualities **actually returned** for a single file. Select one or several and tap Done. For an exposed folder listing, the bot reports how many files have usable links, asks for an inclusive range, then presents the qualities in that range. Files and selected quality variants are transferred **one by one**, with their real filename extension, MIME, and size (when provided). For video thumbnails the bot tries the file's API preview URL, then the parent listing's preview, applying the same redirect checks, blank-image rejection, and Telegram-compatible JPEG resize used for YouTube. If both fail, it makes one bounded, single-threaded attempt to extract a frame from the video sample already captured during streaming (no second full download); some streams cannot be decoded from this sample, so a thumbnail cannot be guaranteed. The same inline-playback and post-send cover check described for YouTube applies to Terabox videos. If the API reports a folder total but does not expose links for all files, the bot can only process the returned links; it cannot traverse an unlisted folder. Repeated entries with the same file ID and different qualities are treated as one file with multiple choices. The bot refreshes expiring links before transfer when the API supplies `expires_at`. Terabox mode does not accept YouTube links, and vice versa. `/changeapi` only changes the YouTube provider; the Terabox API is fixed. Signed links may expire during long jobs, and neither service bypasses private/blocked content.

## Koyeb deployment (Docker)

1. Create a Telegram bot with BotFather; keep its bot token secret. Get an **API ID** and **API hash** for your Telegram application from [my.telegram.org](https://my.telegram.org/).
2. Create a Koyeb Web Service from this repository using its `Dockerfile`. Select the free instance and **one replica only** (multiple instances of the same bot can duplicate work).
3. Configure Koyeb **secret environment variables** `BOT_TOKEN`, `API_ID`, and `API_HASH`. These are required. Do not commit them to the repository. **No string session or user account login is needed**: Telethon logs in as the bot using an in-memory MTProto session and your bot token. A restart creates a fresh login session.
4. Use service port **8000** (`PORT` can override it) and the HTTP health check **`/healthz`**. Telegram updates and uploads use MTProto; the web port is only for Koyeb health checks. No webhook is needed.
5. Optionally set `MAX_FILE_MB` (default 2000, clamped to 1–2000), `MAX_RANGE_VIDEOS` (default 150, clamped to 1–150), and `UPLOAD_IN_FLIGHT` (default 2, clamped to 1–3 upload parts). Send `/start` to your bot.

### Large uploads and free-tier limits

The bot uses **MTProto rather than the standard Bot API upload endpoint**, so its configured per-file limit is **2,000 MiB** (about 2 GB), instead of 50 MB. With 512 KiB parts this is exactly 4,000 parts, the Telegram client upload-part boundary; larger sizes such as 2,047 MiB would need too many parts and are rejected before transfer. If a media URL supplies `Content-Length`, the bot streams bounded 512 KiB chunks directly from the provider into Telegram's MTProto upload; it does **not** save the whole video on Koyeb or load it into RAM. It checks the declared and actual size. The transfer must remain accessible throughout the upload. If a Terabox URL omits `Content-Length` but the API supplied `size_bytes`, that size is checked against the actual stream and used for bounded streaming. Otherwise, a missing length temporarily spools files up to **64 MiB** to discover their size, and skips larger unknown-size files. Redirects must remain on public HTTPS hosts.

Uploads near the 2,000 MiB limit can take a long time and consume significant bandwidth; Koyeb's free-tier network, runtime, and resource limits may interrupt them. Success depends on the provider link staying valid and the Telegram servers accepting the media. A single global transfer slot and four waiting jobs bound concurrent resource use. You can send another link in your active mode and choose its formats while an earlier job is running; each completed selection joins the FIFO queue. One pending format-selection panel per user is supported. The global queue holds at most five jobs total (one active plus four waiting). At most two link lookups run concurrently; playlists are counted using flat metadata and individual video API lookups remain sequential. Temporary files are deleted after use; jobs and selections are in memory and are **not restored** after a restart. Playlist API lookups run sequentially and can take 1–2 minutes *per video*, so a 100-video selection can take a long time. The bot does not transcode or split files.

### Live status and speed

Each time you tap **Done** after choosing qualities, the bot posts a **new combined live status** showing the newly queued job, any running/queued jobs and the five most recent finished/cancelled jobs (retained for six hours while the process runs); it deletes the old status/selection panels where Telegram permits it. `/status` (or `/queue`) likewise replaces the old message with a fresh combined status, including recent finished transfers. Each job displays a tappable `/cancel_JOBID` command rather than a Cancel button. Playlist and folder items show their position in the title, for example `🎬 2/39 · One Way or Another Episode 15 [360p] [MultiSub]`. Finished history is in memory and disappears if Koyeb restarts or redeploys. The status edits automatically approximately every **12 seconds** and has **Refresh all**, which edits immediately and resets the automatic timer; repeat taps within two seconds are ignored to avoid flood waits. The dashboard includes progress bars, source and Telegram bytes, upload speed, ETA, and queue position. If posting a new dashboard fails, the job's selection message still shows its own live progress. Dashboard state is bounded to 100 users; an idle dashboard may be evicted when this limit is reached, and `/status` reopens it. During an API lookup or playlist discovery, size and ETA are not yet known. Resource readings use the **container cgroup CPU quota and RAM usage** (not the Python process alone) when available; Koyeb's dashboard may show a different sampling window. If cgroup data is unavailable, the status says so rather than claiming it matches Koyeb.

The optional native **`cryptg`** accelerator reduces MTProto encryption CPU usage. Large and small known-size uploads pipeline **two 512 KiB parts** by default instead of waiting for each part's round trip. This uses about 1 MiB of in-flight part data per job and keeps the single global transfer limit. On a particularly CPU-constrained free instance, set `UPLOAD_IN_FLIGHT=1`; for faster networks, 2 is the recommended starting value (3 is the maximum). Throughput is still limited by the provider, Telegram, and Koyeb; this cannot guarantee a particular speed.

Only download media you have permission to use. Private, region-blocked, or age-restricted videos are not bypassed.

## Run locally

Python 3.11+ is recommended:

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
export BOT_TOKEN='your-bot-token'
export API_ID='your-numeric-api-id'
export API_HASH='your-api-hash'
python -m ytdown
```

Offline tests require neither credentials nor network access:

```sh
python -m unittest discover -s tests -v
```

## Commands

- `/start` or `/help` — usage instructions
- `/change` — YouTube-only / Terabox-only mode buttons; mode changes affect future links, not queued transfers, and clear any stale `/changeapi` URL prompt
- `/status` or `/queue` — replace the old status with one live dashboard showing running, queued, and recent finished jobs; selecting a quality and tapping Done also posts a fresh dashboard automatically
- `/cancel` — list your running/queued job IDs and tappable `/cancel_JOBID` commands without stopping anything; `/cancel_JOBID` stops exactly that job, even if it is running. `/cancel JOB_ID` remains supported. `/cancel lookup` stops a pending link lookup. If no jobs are active, `/cancel` clears a pending selection or lookup.
- `/apis` — numbered list of the built-in YouTube and Terabox APIs and your current YouTube override (if any); `/apis remove 3` removes only your custom override. Built-in APIs cannot be removed.
- `/changeapi` — prompt for your personal public HTTPS API endpoint; you can also use `/changeapi https://example.com/?url=` directly. The bot supplies the normalized YouTube link as `url=`. `/changeapi show` indicates whether an override is set; `/changeapi reset` (or `remove`) returns to the built-in API. Changes affect **future** selections; already selected/queued jobs retain their API. Sending a valid media link while the `/changeapi` prompt is open treats it as a media link, not a replacement API. Settings are in memory and reset after a Koyeb restart. Do not put secret tokens in the API URL if you do not want them held in memory.
- `/limits` — current upload, playlist-range, and queue limits

In YouTube mode, a watch URL containing `list=` is treated as a playlist; remove that parameter to download only the video. `youtu.be` links are treated as single videos. Playlists must be publicly discoverable through `yt-dlp`; keep `yt-dlp` updated if YouTube changes its site.
